# Revenge Classic runtime evidence

Checked on 2026-10-13. Official Classic v1.11.6 commit is `1b1d297416594087769987908e5fc09af36b7e6e`. Downloaded source files in `work/research-classic`; official current Next template is not the Classic plugin format.

## Loader and APIs (official Classic source)

- [Vendetta Source URL loader](https://github.com/revenge-mod/revenge-bundle/blob/1b1d297416594087769987908e5fc09af36b7e6e/src/core/vendetta/plugins.ts): normalizes source directory with trailing `/`, fetches `manifest.json` and manifest `main` (fallback `index.js`). Manifest `hash` controls updates; unchanged hashes skip JS fetching. Evaluates `vendetta => { return ${plugin.js} }` and invokes a returned function if needed; takes `.default` when present. Bundle must be an expression/IIFE returning `{onLoad,onUnload,settings}`, not CommonJS/ESM or Next ZIP.
- [Vendetta API](https://github.com/revenge-mod/revenge-bundle/blob/1b1d297416594087769987908e5fc09af36b7e6e/src/core/vendetta/api.tsx): injected scoped `vendetta.plugin.storage`, logger, `metro.findByProps`, `findByStoreName`, `findByName(name, defaultExp=true)`, `metro.common.React`, `ReactNative`, `FluxDispatcher`. Does **not** expose JSX creation hooks. Vendetta plugin patches/listeners are not auto disposed; `onUnload` must undo them.
- [JSX hooks](https://github.com/revenge-mod/revenge-bundle/blob/1b1d297416594087769987908e5fc09af36b7e6e/src/lib/api/react/jsx.ts): `bunny.api.react.jsx.onJsxCreate(name, callback)` returns nothing. Callback is `(Component, element)`; return replacement element or `undefined`. `deleteJsxCreate(name, sameCallback)` unregisters. Both `jsx` and `jsxs` patched. Only a function component with matching `Component.name` qualifies; native string components and memo objects do not.
- [Classic initialization](https://github.com/revenge-mod/revenge-bundle/blob/1b1d297416594087769987908e5fc09af36b7e6e/src/index.ts) assigns `window.bunny = lib` before starting Vendetta plugins. JSX hooks therefore resolved from `globalThis.bunny.api.react.jsx`; this does not invoke Next APIs.
- [Patcher signatures](https://github.com/revenge-mod/revenge-bundle/blob/1b1d297416594087769987908e5fc09af36b7e6e/src/lib/api/patcher.ts): `before(methodName,parent,(args)=>void|replacementArgs)`, `after(methodName,parent,(args,result)=>replacementResult)`, `instead(methodName,parent,(args,original)=>result)`; each returns unpatcher. The runtime uses only `before` on the native bridge.
- [Dispatcher types](https://github.com/revenge-mod/revenge-bundle/blob/1b1d297416594087769987908e5fc09af36b7e6e/src/metro/common/types/flux.ts): `subscribe(actionType, callback):void`, `unsubscribe(actionType, sameCallback):void`, `dispatch(payload):Promise<void>`, `wait(callback):void`. `FluxDispatcher` resolves via `_interceptors` in [common/index.ts](https://github.com/revenge-mod/revenge-bundle/blob/1b1d297416594087769987908e5fc09af36b7e6e/src/metro/common/index.ts).

## Native chat evidence (primary existing plugin implementations)

- [maisymoe/strife ReactChat row type](https://github.com/maisymoe/strife/blob/54f4768ef41d66e682a0917b078129df5c34f0f8/plugins/ReactChat/src/def.d.ts) defines a native row `type:number`, `index:number`, `message:{id,channelId,guildId,content:string,...}`. Its [bridge interceptor](https://github.com/maisymoe/strife/blob/54f4768ef41d66e682a0917b078129df5c34f0f8/plugins/ReactChat/src/patches/interceptor.ts) patches `ReactNative.NativeModules.DCDChatManager.updateRows`: argument 1 is JSON array of rows, argument 0 logIndex, argument 2 boolean. Its comments explicitly warn updates are incremental. Component source leaves content parsing as TODO and replaces the whole Chat, so it is not proof of a per-message RN component.
- [redstonekasi message-logger](https://github.com/redstonekasi/vendetta-plugins/blob/50c6afcca1c2390db494292a2bf238bd0b34b352/plugins/message-logger/src/index.ts): resolves `RowManager`, patches `generate` for `data.rowType === 1`, and reads `channel_id` from message records. Channel message collections contain `_array`. This supports native rows and source-record identity, not mutating store records for this translator.
- [fres621 FileContentPreview native bridge patch](https://github.com/fres621/vendetta-plugins/blob/a55fb008acb5dc4b90bc195ad21768a3d2638653/plugins/FileContentPreview/src/patches/RowManager.ts): on builds greater than `200013`, uses `before('updateRows', DCDChatManager, args)` and JSON parses/serializes argument 1; older builds use `after('generate', RowManager.prototype, ...)`.
- Current `bleelblep/revenge-next-plugins` sources provide **native schema evidence only**, not Classic APIs. Pinned commit `b873b18c8f19fb3f6326c42b07418c2ea0a699af`: [Translate native row serializer](https://github.com/bleelblep/revenge-next-plugins/blob/b873b18c8f19fb3f6326c42b07418c2ea0a699af/plugins/translate/js/patches/rowManager.ts) checks `Array.isArray(message.content)` and assigns a new array. Its comments identify Discord 348.x memoized MarkupParsers and native ContentNodeSerializer accepting string primitives. [Veil native row implementation](https://github.com/bleelblep/revenge-next-plugins/blob/b873b18c8f19fb3f6326c42b07418c2ea0a699af/plugins/veil/js/patches/rows.ts) appends a newline and `{type:'subtext',content:[note]}` to an existing content array while preserving original nodes. No source implementation was copied into this plugin.
- [Native chat batch protocol](https://github.com/bleelblep/revenge-next-plugins/blob/b873b18c8f19fb3f6326c42b07418c2ea0a699af/plugins/screenshot-redactor/js/lib/chatRows.ts) explains `changeType` values 0 NOOP, 1 INSERT, 2 UPDATE, 3 DELETE, native indices, inserts forwards followed by updates/deletes backwards, and `clearRows(tag)` resetting the native list. This is why replays must send UPDATE rows rather than repeat INSERTs. [Native manager discovery](https://github.com/bleelblep/revenge-next-plugins/blob/b873b18c8f19fb3f6326c42b07418c2ea0a699af/plugins/screenshot-redactor/js/patches/chatManager.ts) supports finding a Metro module with `DCDChatManager` when ReactNative/native globals are unavailable; the adapter uses Classic `findByProps` for that discovery.
- [Already-drawn message regeneration](https://github.com/bleelblep/revenge-next-plugins/blob/b873b18c8f19fb3f6326c42b07418c2ea0a699af/plugins/translate/js/lib/repaint.ts) dispatches a local `MESSAGE_UPDATE` with the exact untouched MessageStore record to request a native row regeneration. The Classic adapter uses Classic's own FluxDispatcher for this pattern; no Next imports or network Discord actions are used.

## Adapter implementation and limits

`src/runtime/classic.ts` uses MessageStore/SelectedChannelStore discovery, store listeners plus Flux subscriptions; loaded messages are snapshots and there are no Discord history requests. Strict IDs are snowflake strings; index is never interpreted as a Discord message ID. Store record content is never overwritten.

Independent RN insertion probes `MessageContent`, `MessageBody`, `ChatMessage`, `MessageRow`. These names are heuristic runtime candidates, not verified Discord 348.10 component names. Props must expose an actual `message`, `item.message`, or `messageRecord`; ID, channel and content must match MessageStore. Original React element is passed unchanged to the consumer. Diagnostics distinguish hook registration from observed validated renders.

Native fallback patches JSON bridge arguments with a new argument array and parsed copies only. Native row identity is checked against MessageStore. Plain-string content requires exact source-text equality, so serialized AST strings are rejected. Arrays must contain strings or typed node objects; existing nodes are preserved and a new newline/subtext/translation section is appended. Source revisions guard replays after edits. At most 1000 original rows are retained; beyond that no additional rows are translated. Original snapshots accumulate across incremental bridge calls; native index shifts follow INSERT/DELETE batches and repaint rows use UPDATE. Native `clearRows` and tag/channel changes reset snapshots. Settings changes and unload restore/replay only the current channel. Once valid independent JSX is observed, native translations are restored and fallback stops adding sections.

For translations ready before their native rows were captured, the adapter requests a local repaint with the exact current store record. Requests are deferred outside reducers, recheck channel/revision/existence, and are bounded to 500 exact source/target/translation keys to prevent feedback loops. Disable/channel/tag reset discards those keys. No source record fields are written and no additional Discord history is fetched.

Tests verify source/argument immutability, loaded record shape, event consumers, JSX original identity, callback cleanup, native arrays, incremental replay, clear/retranslate, unsupported shapes, stale channel/revision protection, INSERT/DELETE index shifts, UPDATE replays, RN/native duplicate suppression and one-time exact-record loaded-message repaint. All 13 focused runtime tests and TypeScript project checks passed. A phone with Android 16 / Discord 348.10 is not connected, so actual native module name, row format, local repaint effectiveness, layout and scroll remeasurement are not end-to-end verified.
