## 0.1.2 原生消费者对象身份修复

用户确认 0.1.1 能加载插件，读取 25 条消息，状态有译文记录，原生观察及改写计数增加，但频道仍只有英文。由此不能把统计数解释为屏幕显示成功。

新增保留原生生成行引用的消费者回归测试：旧实现返回复制的行，保留的原生行仍是原文。四项新增测试在旧实现实际失败。修复保留生成行及生成消息对象，只替换该生成消息的正文属性为新数组；不改 MessageStore 记录、不改共享解析数组或原有节点。保留原文快照，清除/卸载只恢复插件自己的属性写入，其他插件后来写入的内容保持不变。缓存复用行不会反复追加译文。统计文案改为“已取得译文”，诊断不再宣称手机显示已生效。

完整检查包含 69 项自动测试、严格类型检查、编译和 Classic 表达式加载/生命周期验证。此测试确认保留对象的受控消费者修复，不证明用户 Discord 内部一定采用该消费路径；现有 Android 348 渲染参考源码使用生成消息正文属性写入，是本次兼容性选择的证据。0.1.2 手机实际显示效果仍待用户更新后确认。

## Bing 真实网络测试

`npm run probe:bing`，退出码 0：**8/8 通过**。当前发布源码实际请求并检测了简体中文、英语、日语、韩语、德语、法语、俄语、西班牙语；中文译为英语，其余七种译为简体中文。结果、耗时与 UTC 时间见 [live-bing-results.json](live-bing-results.json)。测试使用公开固定样例，没有私人聊天或 API Key。

首次验证脚本把简体中文的预期代码写成 `zh`，Bing 实际返回 `zh-Hans`，译文本身成功。已修正预期为服务真实代码并重新执行全部样例，8/8 通过。不能把修正测试标签当作修复翻译服务。

请求运行在 Windows Node Fetch，并设置一致的 Android 浏览器 User-Agent。它不是 Android 手机测试，样例成功也不是稳定性或可用率保证。限流、风控、地区和服务变化仍可能导致失败。
