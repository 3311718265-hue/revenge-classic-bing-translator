# Bing and Microsoft provider evidence

Checked on 2026-10-13 with fixed public sample text, Windows Node v24.19.0 and this host's current network. No private Discord messages, cookies or session tokens were saved. This short sample does not establish long-term stability.

The Bing translator page redirected from www.bing.com to cn.bing.com and exposed the webpage helper, IG and IID needed by the undocumented ttranslatev3 endpoint. Native requests detected eight sample languages correctly: Chinese, English, Japanese, Korean, German, French, Russian and Spanish. Simplified Chinese source requests to those seven other languages and Traditional Chinese also returned translations. Omitting IG/IID returned HTTP200 / JSON400; an invalid token returned HTTP200 / JSON205. The provider handles application errors in successful HTTP responses and refreshes 205 once.

1,000 and 1,001 character samples succeeded; 5,001 returned JSON400. The exact server limit was not determined. The provider's 1,000 UTF-16 unit chunk size is a conservative client policy, not a server guarantee. Chunks run sequentially, prefer boundaries, preserve boundary whitespace and avoid splitting emoji surrogate pairs. Discord code, mentions, emoji markup, @everyone/@here and URLs stay local and are reinserted exactly. Splitting around these spans can reduce translation context; this is not a complete Markdown parser.

Node's default Fetch UA produced HTTP401 on translation POST, while paired page/POST calls with a consistent Android browser UA succeeded. Referer and explicit Content-Length did not fix the default-UA failure. The provider consistently sets a browser User-Agent and lets the transport compute Content-Length. No cookie jar is needed by the successful probes. Regional page origins are validated and reused for POSTs.

The actual production `createTranslator` module was exercised live and returned EN→ZH, JA→ZH and EN→DE translations. The final sample retained the fake mention `<@123456>`, `https://example.com` and inline code exactly. No official Microsoft authenticated call was made; key/region/JSON/body/endpoint construction was verified by tests. Eighteen provider tests passed, along with a strict ES2020 TypeScript compile. Tests cover session retry bounds, 429 Retry-After, 503 retry, fetch/body timeout, abort, stalled gate cancellation, chunk/token preservation, shared session, explicit fallback, invalid responses and credential endpoint validation.

Every request passes through the rate gate, including session acquisition, retry, refresh and chunk. One delayed retry is allowed for network errors, HTTP408/5xx and Bing205. HTTP429 is surfaced with retryAfterMs and does not trigger an immediate retry/fallback. Caller abort and timeout do not trigger official fallback. The factory snapshots config, serializes translations and caches Bing sessions conservatively for nine minutes. It uses Fetch/AbortController and ES2020 JavaScript without Node/BDFDB networking dependencies.

Official Microsoft is optional and requires a user-supplied API key. Source auto-detection omits `from`; global resources use the key header, while regional/multi-service resources also need their region header. Microsoft HTTPS hosts are validated before credentials are sent. Standard global, geographic and custom-resource text API paths are supported. Official fallback requires an explicit setting plus a key; default operation remains Bing-only.

[React Native networking](https://reactnative.dev/docs/network) and [AbortController](https://reactnative.dev/docs/global-AbortController) document the APIs and known redirect/cookie limitations. These Windows/UA-emulated checks do not prove the user's installed Android16 Discord RN/Hermes runtime. Actual installation, header/redirect/cancellation behavior and Discord integration still require device verification. No rate limit was deliberately induced; no token expiry timing, abuse challenge, large-scale quota or uptime guarantee was tested.

Official primary references: [Translate v3 method](https://learn.microsoft.com/en-us/azure/ai-services/translator/text-translation/reference/v3/translate), [authentication and region](https://learn.microsoft.com/en-us/azure/ai-services/translator/text-translation/reference/authentication), [service limits](https://learn.microsoft.com/en-us/azure/ai-services/translator/service-limits). Current dedicated official limits allow 50,000 total characters across targets; they do not describe the Bing webpage endpoint.
